⚽ Football Club – FC Dynamo Fan Zone
📌 Описание проекта
FC Dynamo Fan Zone — это веб-приложение для болельщиков футбольного клуба, предоставляющее актуальную информацию о команде, расписании матчей, новостях, а также возможность покупки билетов на домашние игры. Платформа ориентирована на создание единого цифрового пространства для фанатов: от просмотра состава и статистики до онлайн-бронирования мест на стадионе. Проект направлен на повышение вовлечённости болельщиков и автоматизацию билетной системы.

🎯 Целевая аудитория

Болельщики футбольного клуба (от подростков до взрослых)

Люди, желающие посетить матчи вживую или следить за командой онлайн

Журналисты и блогеры, освещающие футбольные события

Административный персонал клуба (для управления контентом)

⚙ Ключевой функционал

📰 Просмотр новостей и анонсов клуба

👥 Состав команды (список игроков с фото и позициями)

🗓 Расписание матчей (календарь, результаты прошедших игр)

🎟 Покупка билетов на матчи (выбор сектора, места, онлайн-оплата)

🔐 Регистрация и авторизация болельщиков

⭐ Добавление матчей/новостей в избранное

👤 Личный кабинет (история билетов, избранное)

🛠 Админ-панель для управления контентом (новости, игроки, матчи)

📑 Основные разделы сайта

Название раздела	 Описание раздела

Главная         	 Баннеры с ближайшим матчем, последние новости, турнирная таблица (/)
Аутентификация	   Регистрация / Вход / Восстановление пароля (/auth/*)
Новости	           Список новостей клуба с фильтрацией по дате, категориям (/news)
Команда	           Состав: фото, имя, амплуа, номер, статистика (/team)
Расписание/Матчи	 Календарь игр (будущие и прошедшие), результаты, ссылка на билеты (/matches)
Билеты	           Выбор матча → выбор сектора и места → оформление заказа (/tickets)
Личный кабинет	   Профиль болельщика, история покупок, избранное (/profile)
Контакты	         Контакты стадиона, форма обратной связи, схема проезда (/contacts)
Админ-панель	     Управление новостями, игроками, матчами, заказами билетов (/admin)

🛠 Технологический стек

🖥 Frontend – Vue.js

Почему выбран Vue.js:
Компонентная архитектура для переиспользования (карточка новости, игрока, матча)

Реактивность – мгновенное обновление расписания при смене фильтров

Простота создания SPA с плавными переходами между разделами

Высокая производительность при работе с динамическими списками (например, состав команды)

Vue Router – для маршрутизации (динамические страницы /matches/:id, приватные маршруты /profile, /admin)

🛠 Backend – Node.js + Express
Почему Node.js + Express:

Единый язык (JavaScript) на клиенте и сервере

Асинхронная обработка запросов при покупке билетов (работа с БД )

Лёгкая маршрутизация API (/api/news, /api/matches, /api/tickets)

Гибкие middleware для аутентификации (JWT) и проверки ролей

🗄 База данных – MySQL

Почему MySQL:
Реляционная структура для связей: пользователи → заказы → билеты, матчи → команда

Поддержка сложных SQL-запросов (фильтрация матчей по дате, получение состава команды)

Надёжность и целостность данных (транзакции при продаже билетов)

🌐 Инфраструктура

Frontend хостинг: GitHub Pages (бесплатно, автоматический деплой)

Backend сервер: Node.js (Express) на виртуальной машине (например, на Render или VPS)

База данных: MySQL (облачный сервис типа ClearDB или локальный на VPS)

Взаимодействие:

Пользователь открывает сайт → Frontend (Vue) загружается

Клиент отправляет API-запросы на Backend (например, GET /api/matches)

Backend обращается к MySQL, формирует JSON-ответ

Frontend отображает данные (например, календарь матчей)

🎨 Визуальное проектирование интерфейса
1. Главная страница (/)
Тип доступа: Публичный

Основные блоки:

Header: логотип, поиск, кнопка «Войти» / аватар с меню

Hero-секция: баннер ближайшего матча (дата, соперник, кнопка «Купить билет»)

Последние новости: 3 карточки новостей (заголовок, дата, краткий текст)

Турнирная таблица: таблица чемпионата (место, команда, очки)

Footer: контакты, соцсети, ссылки на разделы

Динамический контент:
GET /api/matches?next=true – ближайший матч
GET /api/news?limit=3 – последние новости
GET /api/standings – турнирная таблица

2. Страница аутентификации (/auth)
Тип доступа: Публичный

Блоки:

Форма входа (email, пароль)

Форма регистрации (имя, email, пароль, ключевое слово для восстановления)

Форма восстановления пароля (email, ключевое слово, новый пароль)

API:
POST /api/auth/login
POST /api/auth/register
POST /api/auth/reset-password

3. Новости (/news)
Тип доступа: Публичный

Блоки:

Фильтры (по дате, по категории: «трансферы», «матчи», «клуб»)

Сетка новостей (карточка: заголовок, дата, изображение, краткий текст)

Пагинация

API:
GET /api/news?category=transfers&page=1
GET /api/news/:id – детальная новость

4. Команда (/team)
Тип доступа: Публичный

Блоки:

Список игроков по амплуа (вратари, защитники, полузащитники, нападающие)

Карточка игрока: фото, имя, номер, позиция, ссылка на детальную статистику

Детальная страница игрока (/team/:id) – полная статистика, биография

API:
GET /api/players – список игроков
GET /api/players/:id – детальная информация

5. Расписание / Матчи (/matches)
Тип доступа: Публичный

Блоки:

Переключатель «Будущие матчи» / «Прошедшие матчи»

Список матчей: дата, соперник, место проведения, счёт (для прошедших)

У каждого будущего матча – кнопка «Купить билет»

API:
GET /api/matches?status=upcoming
GET /api/matches/:id – детальная страница матча (составы, статистика)

6. Билеты (/tickets)
Тип доступа: Авторизованный пользователь (только для покупки)

Блоки:

Выбор матча из выпадающего списка (только будущие)

Схема стадиона (интерактивная) – выбор сектора и места

Количество билетов, итоговая цена

Кнопка «Оформить заказ» (перенаправление на платёжный шлюз)

API:
POST /api/orders – создание заказа (передача выбранных мест)
GET /api/orders/:id – статус оплаты

7. Личный кабинет (/profile)
Тип доступа: Авторизованный пользователь

Блоки:

Информация о пользователе (имя, email, дата регистрации)

История заказов (номер заказа, матч, места, статус)

Кнопка «Редактировать профиль»

Кнопка «Выйти»

API:
GET /api/users/me
PUT /api/users/me
GET /api/users/me/orders

8. Избранное (/favourites)
Тип доступа: Авторизованный пользователь

Блоки:

Две вкладки: «Избранные новости» / «Избранные матчи»

Для новостей – карточки с возможностью удаления

Для матчей – карточки матчей с кнопкой «Купить билет»

API:
GET /api/users/me/favourites?type=news
DELETE /api/users/me/favourites/:id
POST /api/users/me/favourites/:entityType/:entityId

9. Админ-панель (/admin)
Тип доступа: Только администратор

Блоки:

Управление новостями: список новостей, кнопки «Добавить»/«Редактировать»/«Удалить»

Управление игроками: CRUD для состава команды

Управление матчами: создание/изменение расписания, ввод результатов

Управление заказами: просмотр всех заказов билетов

API:
POST /api/news – создание новости
PUT /api/news/:id – редактирование
DELETE /api/news/:id – удаление
(аналогично для /api/players, /api/matches)

🗃 Схема данных и API
Основные модели данных
1. Пользователь (User)
Поле	Тип	Описание
id	integer	Уникальный идентификатор
name	string	Имя болельщика
email	string	Email (уникальный)
password	string	Хэш пароля
secretWord	string	Хэш ключевого слова для восстановления
role	enum	user или admin
createdAt	datetime	Дата регистрации
2. Новость (News)
Поле	Тип	Описание
id	integer	ID новости
title	string	Заголовок
content	text	Полный текст
imageUrl	string	Ссылка на изображение
category	string	transfers, match, club
publishedAt	datetime	Дата публикации
isImportant	boolean	Важная новость (баннер)
3. Игрок (Player)
Поле	Тип	Описание
id	integer	ID игрока
name	string	Полное имя
number	integer	Игровой номер
position	string	goalkeeper, defender, midfielder, forward
photoUrl	string	Фото
birthDate	date	Дата рождения
nationality	string	Гражданство
stats	JSON	Статистика (голы, матчи)
4. Матч (Match)
Поле	Тип	Описание
id	integer	ID матча
opponent	string	Название команды-соперника
dateTime	datetime	Дата и время начала
venue	string	home (дома) или away (выезд)
homeScore	integer	Голы хозяев (для прошедших)
awayScore	integer	Голы гостей
status	string	upcoming, finished
5. Заказ (Order) и Билет (Ticket)
Order (заказ на билеты)

Поле	Тип	Описание
id	integer	ID заказа
userId	integer	ID пользователя (внешний ключ)
matchId	integer	ID матча
totalPrice	decimal	Общая стоимость
status	string	pending, paid, cancelled
createdAt	datetime	Дата создания заказа
Ticket (отдельный билет, может быть несколько на один заказ)

Поле	Тип	Описание
id	integer	ID билета
orderId	integer	ID заказа (внешний ключ)
sector	string	Сектор стадиона
row	integer	Ряд
seat	integer	Место
Связь «Избранное» (Favourites)
Таблица для связи пользователей с новостями/матчами (полиморфная связь или две отдельные таблицы). Для простоты – отдельная таблица user_favourites:

Поле	Тип	Описание
id	integer	ID записи
userId	integer	ID пользователя
entityType	string	news или match
entityId	integer	ID новости или матча
API Эндпоинты
Аутентификация
Метод	Эндпоинт	Описание
POST	/api/auth/register	Регистрация
POST	/api/auth/login	Вход (возвращает JWT)
POST	/api/auth/reset-password	Сброс пароля
Пример тела запроса (регистрация):

json
{
  "name": "Алексей",
  "email": "fan@example.com",
  "password": "securePass123",
  "secretWord": "mySecret"
}
Ответ (успешный вход):

json
{
  "token": "jwt_token_here",
  "user": {
    "id": 1,
    "name": "Алексей",
    "email": "fan@example.com",
    "role": "user"
  }
}
Новости
Метод	Эндпоинт	Описание
GET	/api/news	Список новостей (с фильтрацией)
GET	/api/news/:id	Детальная новость
POST	/api/news	Создать (только админ)
PUT	/api/news/:id	Обновить (админ)
DELETE	/api/news/:id	Удалить (админ)
Пример GET /api/news?category=transfers&page=2

Игроки
Метод	Эндпоинт	Описание
GET	/api/players	Список всех игроков
GET	/api/players/:id	Детальная информация
POST	/api/players	Добавить игрока (админ)
PUT	/api/players/:id	Редактировать (админ)
DELETE	/api/players/:id	Удалить (админ)
Матчи
Метод	Эндпоинт	Описание
GET	/api/matches	Список матчей (параметр status)
GET	/api/matches/:id	Детали матча
POST	/api/matches	Создать матч (админ)
PUT	/api/matches/:id	Обновить (счёт, статус) (админ)
DELETE	/api/matches/:id	Удалить матч (админ)
Пример GET /api/matches?status=upcoming

Заказы и билеты
Метод	Эндпоинт	Описание
POST	/api/orders	Оформление заказа (требуется JWT)
GET	/api/users/me/orders	История заказов текущего пользователя
GET	/api/orders/:id	Детали конкретного заказа
PUT	/api/orders/:id/cancel	Отмена заказа (если не оплачен)
Тело POST /api/orders:

json
{
  "matchId": 5,
  "tickets": [
    { "sector": "A", "row": 10, "seat": 15 },
    { "sector": "A", "row": 10, "seat": 16 }
  ]
}
Избранное
Метод	Эндпоинт	Описание
GET	/api/users/me/favourites?type=news	Получить избранное
POST	/api/users/me/favourites/news/:id	Добавить новость в избранное
DELETE	/api/users/me/favourites/news/:id	Удалить из избранного
POST	/api/users/me/favourites/matches/:id	Добавить матч в избранное
DELETE	/api/users/me/favourites/matches/:id	Удалить матч из избранного
Админ-панель (все CRUD-эндпоинты защищены ролью admin)
Управление новостями: как указано выше

Управление игроками: как указано выше

Управление матчами: как указано выше

Просмотр всех заказов: GET /api/admin/orders

🔐 Права доступа (роли)

Роль	Доступные разделы
User	Главная, Новости, Команда, Матчи, Билеты (покупка), Профиль, Избранное, Контакты
Admin	Всё, что у User + Админ-панель (управление контентом и заказами)
